# P1 / P2草案: Cycle 8 Take2 業務仕様再整理（目標時間の確立・配置時間差分化・不足時通知・テスト安定化）

## 背景と目的
Cycle 8 Take1（commit `3fd2029` / 差分レビュー `docs/handoff/P4_Dex_Review/cycle_8_review.md`）において指摘された、勤務時間の計算根拠（一律8時間換算による短時間社員・パートへの誤表示と「残業」表記の不適切さ）、および希望休自動配置における空きセル不足時の無言終了、恒久テストのパフォーマンス（タイムアウト）問題を根底から解決するため、Air(P1)が業務仕様を正式に再定義します。

本改修は、従業員データ構造への目標時間保存項目（`targetHours`）追加および判定ロジックの見直しを含むため、「危険領域タスク」としてDex(P2)への事前監査へ回します。

---

## 1. Air が確定した4大業務仕様（仕様判断）

### (1) 月間目標時間の持ち方（保存項目の追加）
- **仕様決定**: 従業員オブジェクトに **「月間目標時間 (`targetHours`)」** という明示的な任意入力・保存項目を新たに追加します。
- **UI導線**: 従業員の編集・登録画面（または設定表）の項目として、目標時間を数値（例: `80`, `160`, `64` 等、小数点も許容、未入力は空欄または `null` / `undefined` / `""` / `0`）で保持させ、localStorageおよびエクスポート/インポートの対象に含めること。
- **一律 8h の廃止**: 従来 TAKE1 のように `契約日数 × 8h` を勝手に計算するコードは**完全廃止（禁止）** します。短時間勤務者（1日3h〜7h等）でも各自の契約・目標値と整合させます。

### (2) 既存ユーザーの初期値・移行値および「目標未設定」時の表示仕様
- **移行方針（既存データ）**: 既存のユーザー・スタッフ名簿データには `targetHours` 項目が存在しないため、マイグレーション等で勝手な数値を強制埋め込みせず、デフォルトで **「未設定 (空値・`null`/`undefined`/`0` または `""`)」** として扱います。
- **目標未設定時の画面表示**:
  - `targetHours` が無効または設定されていない従業員については、青・赤の過不足判定や数字の差分表示を一切行いません！
  - PC版のセルおよびスマホ版の名前タップドロワー内のいずれにおいても、シンプルかつ安全に **「目標未設定」** と表示するのみとします。

### (3) 休憩時間の扱いと表記名の変更（「残業判定」→「配置時間差分」）
- **業務定義と名称改革**:
  - 現在のシフト時間割り当ては「出勤から退勤までの時間（休憩込み経過時間）」をベースに計算されており、実際の法定残業判定に直接用いることは不本意かつ誤謬を招き得ます。
  - したがって、UIおよびコード内の概念・機能名称を **「残業・不足警告」から「目標との配置時間差分（または時間差分）」へと正式に変更・統合** します。
- **時間単位の整合**: 実績（休憩込み・シフト時間総和）に対して、ユーザーが設定する目標時間（`targetHours`）も同じ「シフト上の配置目安時間」としての比較対照とします。
- **差分閾値の判定仕様 (実績 - 目標)**:
  - 目標時間が有効な数値として存在する際のみ差分（`delta = elapsed - targetHours`）を算出する。
  - **`+2.0h < delta`** : **`+XX.Xh (超過)`** （朱赤 / アンバーなどの注意色、背景 `#FEF2F2` 等）
  - **`delta < -2.0h`** : **`-XX.Xh (不足)`** （ブルー系の注意色、背景 `#EFF6FF` 等）
  - **`-2.0h <= delta <= +2.0h` (ちょうど -2.0h および +2.0h を含む)** : **`±XX.Xh (標準)`** または緑／標準色（超過・不足警告対象外！）
  - **目標未設定時** : 色分けなし、**「目標未設定」**（警告対象外）

### (4) 空きセル不足時（抽選で希望休日数を満たせなかった場合）の通知UI
- **処理ルールの維持**: 「既に埋まっている確定済みシフトは絶対に維持する・壊さない」方針を厳守。まず空きセルを洗い出した上で、正社員2〜4日・パート5〜8日等の目標希望休の自動配置を試みます。
- **不足検出と明示通知 (通知UI)**:
  - 空き日数や抽選上限（打ち切り）の制約で目標配置数に満たないスタッフが発生した場合、これまでの無言正常終了を禁止します。
  - ランダム反映後、不足者が1名でもいた場合は即座に **「不足通知アラート／ダイアログ（または画面上部に大きく表示するモーダル/フラッシュバナー）」** で以下のように明示してください：
    ```text
    【一部スタッフの希望休の自動配置が目標数に到達しませんでした（既存確定シフト保護のため）】
    以下の従業員は空き日が不足しています：
    ・ 山田 早来: （目標 5 日 ➡ 配置 3 日）
    ・ 佐藤 正男: （目標 3 日 ➡ 配置 1 日）
    ```

## 2. CC (P3 実装担当) 向け 実装およびテスト修正ガイド

Air(P1/P2草案)の仕様定義を受け、CCはTake2にて以下を完全遂行すること：

### A. 実装改修の範囲と絶対の維持
- `App.jsx` などにおける `targetHours` の入出力およびステート管理補完、過不足差分算出の是正（「目標未設定」および超過・不足閾値 `-2.0h`, `+2.0h` 境界値での安全対応）。
- **維持する既存事項**: バックエンドのシフト自動生成ロジック、API通信方式、 Cycle 7の左固定列（105px等）やズーム・スクロール機能は完全に維持・据え置き・改変禁止。
- **バージョン固定**: バージョン表記は Take2 の完成まで **`v4.30`** のまま進める（引き上げない）。

### B. 全テスト同時実行のタイムアウト (20秒超え) を完全に根絶する軽量化改革
- **事象と対策**: `App.cycle8.test.jsx` にて、1つのテストで 22個の select 変更を直列ループで実行し、画面が 22回フル描画されたことで 20s タイムアウト事故（47/48 PASS）を招いた。
- **是正指針**: `fireEvent.change` を22回繰り返し実行するような負荷テストは破棄し、**あらかじめ目的のテスト用状態（シフト時間超過や目標設定済の従業員レコード等）を直接ステート初期化／ localStorage への事前モック投入によって即座に組み立て、1回（または最少）のレンダーだけで超過・不足・目標未設定表示が確実に描画されるかどうかを即検証する構成** へ全面的に最適化してください。

### C. 不足している恒久テストの網羅追加 (MUST)
以下の重要経路・期待する状態遷移を検証するテストケースを `App.cycle8.test.jsx` 等へ補完すること：
1. **確定シフト維持**: 確定済み通常・特殊シフトがある状態で「希望休ランダム自動入力」を実行しても、元の確定シフトを上書き・上り消しせず保持し続けること。
2. **`matrix` と `requests` の一貫性**: 実現したマトリクス上の「休」日付と、`employees[].requests` 内の日付配列が寸分の狂いなく 100% 整合・同期すること。
3. **空きセル不足時の通知トリガー**: 確定シフトをたくさん積んだ狭い空きセルの対象者に対してランダム入力をした際、目標件数未達を検知して通知アラート・ダイアログ・文言等が画面に表示されること。
4. **境界値 (`±2.0h` ちょうど) の判定安全**: 差分がちょうど `-2.0h` ないし `+2.0h` である場合は警告カラーとならず、「標準 / 良好」扱いに収まること。
5. **短時間勤務パートと「目標未設定」の誤検知防止**: 短時間契約者が `targetHours: 64` と設定され実績が 64時間だった場合、不足警告せず「標準」となり、また目標が未入力/空の人は無条件に「目標未設定」となること。
6. **テスト高速完了保証**: 全テスト同時実行 (`npm --prefix frontend test`) を 2周連続で実行し、いかなるタイムアウトをも起こさずに全件（48件超等）がPASSすること。
7. **コンソールおよび実機ブラウザ（1280px / 375px）検証**: 警告およびエラーが 0件であることを徹底すること。
