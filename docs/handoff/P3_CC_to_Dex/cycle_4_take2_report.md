## 変更内容

### 1. リセット確定時に`generatedResult`も破棄（整合性不具合の修正）

`frontend/src/App.jsx`の「デフォルトリセット」ボタンの`onClick`内、`setEmployees(...)`の直後に`setGeneratedResult(null)`を追加しました。既存の`useEffect`（`generatedResult`が`null`になると`localStorage.removeItem('shift_generatedResult')`を実行）により、リセット確定時は`localStorage`上の生成済みシフトも消えます。キャンセル時（`window.confirm`が`false`）はどちらも呼ばれないため、従業員データ・生成済みシフトの両方が保持されます。

### 2. 従業員管理画面での鍵持ち表示

`isKeyHolder: true`の従業員を、ダッシュボード側の既存表現（🔑アイコン）に合わせつつ、従業員管理画面でも識別できるよう以下を追加しました。

- **モバイルカード表示**: 氏名の右側、既存の「登販」バッジと横並びで「🔑 鍵持ち」バッジを追加（`isRS`がない場合はこのバッジのみ表示）。
- **PCテーブル表示**: 氏名セルの右側に、同じく「🔑 鍵持ち」バッジをインラインで追加。

4番目以降（`isKeyHolder: false`）には何も表示されません（`INITIAL_DATA`自体は今回変更していません＝上位3名のみ`true`のまま）。

### 3. 恒久テストの強化

`frontend/src/App.reset.test.jsx`に以下を追加しました（既存2件と合わせて計3件、新規1件はさらに別ケースを追加したため実質+1件）。

- 「確認ダイアログでOKすると24名のデフォルト構成へリセットされ、古い生成済みシフトも消える」: 事前に`shift_generatedResult`をlocalStorageへ仕込み、リセット確定後に`localStorage.getItem('shift_generatedResult')`が`null`になることを直接検証。
- 「確認ダイアログでキャンセルすると従業員リストも生成済みシフトも変更されない」: 同様に事前設定した生成結果が、キャンセル後もlocalStorageに残っていることを検証。
- 「従業員管理画面で上位3名(K.D./N.E./N.K.)にのみ鍵持ち表示があり、4番目以降(T.S.等)には表示がない」: 「🔑 鍵持ち」バッジの出現回数がちょうど3件であること、およびK.D./N.E./N.K.の各セルには「鍵持ち」の文字列が含まれ、T.S.のセルには含まれないことを直接検証。

### 4. バージョン表記

ヘッダー（PC用・モバイル用両方）の`v4.19`表記を`v4.20`に更新しました（`replace_all`で2箇所反映）。
