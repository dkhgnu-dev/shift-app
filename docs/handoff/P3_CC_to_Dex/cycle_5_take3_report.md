## 対応内容

### 固定1列目と氏名列(2列目)の5px重複を解消

**原因**: `frontend/src/index.css`の全セル共通ルール`th, td { ... min-width: 45px; }`が1列目（ドラッグハンドル列）にも適用されていました。1列目はJSX側で`width: 40px`のインラインスタイルを指定していましたが、CSSの`min-width: 45px`の方が優先されるため（`min-width`は`width`より優先度が高い）、実際の描画幅は45pxになっていました。一方、2列目（氏名列）は`left: 40px`で固定していたため、1列目の実際の右端（45px地点）と2列目の左端（40px地点）の間で5px分、両者が重なっていました。

**修正**: 差戻し指示書の推奨案（案1）に従い、1列目を`width: 40px; min-width: 40px; max-width: 40px;`で厳密固定しました。`:nth-child(1)`セレクタは`th, td`より詳細度が高いため、この指定が確実に優先されます。2列目の`left: 40px`は変更していません。

```css
/* frontend/src/index.css */
td:nth-child(1), th:nth-child(1) {
    position: sticky; left: 0; background-color: #F8FAFC; z-index: 30;
    width: 40px; min-width: 40px; max-width: 40px;
}
```

これにより、1列目は0〜40pxの範囲に固定描画され、2列目は40px地点から固定されるため、境界座標が一致し重複が解消される想定です（座標の実測についてはブラウザ実機での確認が必要。下記「実機確認について」参照）。

### CSS仕様に基づく境界一致の根拠（実機測定の代替として。詳細は次項）

`* { box-sizing: border-box }`（`index.css`冒頭で全要素に適用済み）のため、`width: 40px`は border・padding を含んだ実際のボックス幅として扱われます。1列目を`width/min-width/max-width: 40px`で厳密固定したことで、1列目の右端は常にx=40pxの位置になります。2列目は`left: 40px`でスクロール領域の左端から40pxの位置に固定されるため、両者の境界はCSSの仕様上ちょうど一致し、重複・隙間のいずれも生じない設計です。
