### 1. matrixとrequestsの「完全一致」テストを日番号配列の直接比較へ修正

指摘: `App.cycle8.test.jsx:340-355`（旧）のテストは、matrixとrequestsの希望休を「件数」だけで比較しており、matrixが1日・5日、requestsが2日・6日でも件数2件同士として誤ってPASSしてしまう偽陽性があった。

対応: `frontend/src/App.cycle8.test.jsx`の対象テストを、matrixから抽出した希望休の日番号配列と、`employees[].requests`から解析した日番号配列を、双方ソートしてから`toEqual`で直接比較する方式へ書き換えました。

```js
const matrixDays = selects
    .map((s, d) => ({ value: s.value, day: d + 1 }))
    .filter(x => x.value === '希望休')
    .map(x => x.day)
    .sort((a, b) => a - b);
// ...
const requestDays = match[1].split(',').map(s => parseInt(s.trim(), 10)).filter(n => !isNaN(n)).sort((a, b) => a - b);

expect(requestDays).toEqual(matrixDays);
```

### 4. 標準の全件一括実行が完走しない問題（メモリ不安定）への対応

指摘: Dex環境で標準の一括実行（`npm --prefix frontend test`）が3分以上停止し、Nodeプロセスが約1.2GBまで増加。5グループへ分割すれば61/61 PASSすることから、製品ロジックではなくテスト実行のメモリ・分離方法の問題と判断された。

**原因分析**: 既定の`pool: 'threads'`（vitestのデフォルト）は、複数テストファイルを少数のワーカースレッド内で使い回すため、24名×1ヶ月分のマトリクスをまるごとレンダリングする重いテスト（`App.cycle7.test.jsx`21件、`App.cycle8.test.jsx`19→21件など）が同一スレッド内で連続実行されると、V8ヒープが解放されずに蓄積しやすい構造でした。

**対応**: `frontend/vitest.config.js`に以下を追加し、`pool: 'forks'`（ファイルごとに独立したOSプロセスを使う方式）へ切り替え、同時実行数を`maxForks: 2`で明示的に制限しました。

```js
// Cycle8 Take3(Dex差戻し): 既定の`threads`プールは、同一workerスレッド内で
// 複数ファイル分のjsdom+Reactツリーが順次生成されるためV8ヒープが蓄積しやすく、
// Dex環境では標準の一括実行で1.2GB近くまで増加し完走しなかった。
// `forks`プールはファイルごとに独立したOSプロセスを使うため、ファイル完了時に
// メモリが確実に解放される。同時実行数を`maxForks:2`で明示的に抑え、
// ワーカー数を無制限にしないことでピークメモリを予測可能な範囲に収める。
pool: 'forks',
maxForks: 2,
```

**採用理由**: `forks`プールはOSプロセス単位でメモリが分離されるため、ファイル完了時に確実にメモリが解放され、V8ヒープの蓄積によるメモリ増大を防げます。vitest公式ドキュメントでも、jsdom+DOM操作の重いテストスイートで`threads`プールがメモリ増大を起こしやすい場合の代替として案内されている方式です。`maxForks`を無制限にせず`2`に制限することで、このセッションの実行環境でもDex環境でも、同時に立ち上がるプロセス数の上限を予測可能にしています。

**実測**: 本セッション環境（このマシン）では、変更前（`pool: 'threads'`既定）は連続2回で約110〜116秒、変更後（`pool: 'forks', maxForks: 2`）は連続2回で約78〜89秒と、同等かやや高速化し、全61→63件のPASSも維持されました（このセッションではDexが報告したような1.2GB化・完走不能は元々再現していませんでしたが、環境差によるメモリ蓄積リスク自体は`threads`プールの構造上の問題であるため、`forks`への切り替えは有効な対策と判断しました）。テストのcleanup自体（`afterEach(cleanup)`、`vitest.setup.js`）は既存のまま維持しており、追加の変更は行っていません。
