## Findings

### P1: 320～768pxで月度・締め期間が完全に消える

`frontend/src/index.css` のモバイル用 `.header .btn { width: 100%; }` が月移動の左右ボタンにも適用されています。2つのボタンが横幅を使い切り、中央の `.month-header-label` が幅0pxまで縮んでいます。

Dex実測:

- 320px: ラベル幅 0px、左右ボタン各273px
- 375px: ラベル幅 0px、左右ボタン各328px
- 768px: ラベル幅 0px、左右ボタン各721px
- 769px以上: ラベル表示あり

スマホ実画面では左右の矢印だけになり、「2026年7月度 (6/16～7/15)」が見えません。Cycle 5のヘッダー改善要件と逆の状態です。

### P1: 氏名列ではなく空のドラッグ列が固定される

ダッシュボード表は第1列がドラッグ記号、第2列が従業員名です。一方、sticky指定は `th:first-child, td:first-child` だけに適用されています。

右へ350pxスクロールしたDex実測:

- 空のドラッグ列: x=34pxで固定
- K.D.を含む氏名列: x=-176pxへ移動し画面外へ消失

さらに空列へ `min-width: 140px` が付くため、スマホ画面の大部分を空白列が占有しています。利用者が横スクロール中も名前を確認できるという中心要件を満たしていません。

### P1: 日付ヘッダーが縦スクロールで固定されない

`.table-container` が横スクロール祖先になっている一方、高さ制限を持つ縦スクロール領域にはなっていません。そのため `th { position: sticky; top: 0; }` は外側画面の縦スクロールに追従できません。

Dex実測では縦へ700pxスクロール後、表コンテナ上端が-492px、日付ヘッダー上端が-491pxとなり、表と一緒に画面外へ消えました。

表コンテナ自体を適切な高さの縦横スクロール領域にするか、stickyが実際の縦スクロール祖先に対して働く構造へ変更する必要があります。

### P2: MUSTの標準テストが再現せず、レスポンシブ検証にもなっていない

Dex環境で `npm --prefix frontend test` を実行すると、16件中3件が5秒タイムアウトしました。対象テストを個別実行しても、マトリクス表示テストとCycle 4鍵持ちテストのタイムアウトを再現しました。

また `App.matrixScroll.test.jsx` の「スマホ幅相当」テストは `window.innerWidth` をスマホ幅に設定しておらず、jsdomはCSSレイアウトやsticky位置も計算しません。表が存在することは確認できますが、320px表示や固定動作の検証にはなっていません。

標準コマンドが安定してPASSするようテスト構成・タイムアウトを整理し、レスポンシブ/stickyの合否は実ブラウザ検証と分けて報告してください。
