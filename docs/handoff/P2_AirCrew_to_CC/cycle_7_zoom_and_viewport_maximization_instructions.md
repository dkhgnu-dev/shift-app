# P2 指示書: Cycle 7 スマホ版シフト表UI/UX極限最適化（左列100px制限・詳細ポップアップ）及びPC版ワイドズーム統合

## 背景・目的と方針合意
出先相談で得られた「スマホ版（画面幅768px未満）の左側固定列（名前・属性・時間・ドラッグハンドル）が画面の約半分を退治してしまっており、シフト表示エリアが狭くて使いづらい」という重大な根本課題を、PC版の最適化とともに一挙解決します。

本サイクル（Cycle 7）では、以下を達成させ、アプリの使い心地と圧倒的な可視領域を実現します：
1. **スマホ版（`<= 768px` または `isMobileView`）における左固定列の 100px〜110px 厳格軽量化 ＆ ドラッグ手動列の全非表示**
2. **スマホ時の勤務時間・属性等の常時非表示 ➡ 「名前セルタップの軽量ポップオーバー/ドロワー」によるスマート補完UI**
3. **広がったシフト表示エリアの徹底有効化と、スマホ指滑り（スワイプ）専用の快適環境（横スクロール矢印ボタンの非表示化）**
4. **PC版（`> 768px`）における「全月1画面ジャストイン表示」及びズームコントロールと連動する半透明フロートスクロール**

## CC（P3 実装担当）への技術・詳細実装指示

### 1. 【スマホ表示時 max-width: 768px】左側固定列の極限圧縮・軽量化
`isMobileView`（またはメディアクエリ / CSS クラス）が有効な場合、以下の改修を行って左側情報セルの横幅を半分以下へ極小化してください。
- **(A) ドラッグハンドル列（1列目・40px）の強制完全非表示化**:
  - `th:nth-child(1), td:nth-child(1)` で確保されていた並び替え用のドラッグハンドル（`:::` など）のセルを、スマホ環境では完全に `display: none` とする（または JSX の中で `!isMobileView` 条件付き描画を行い、初期の左端を直接名前列にする）。
  - ※スマホ表示時にドラッグ列を除外する場合は、氏名列（従来 `left: 40px` で固定）を **`left: 0px`** への固定に動的変更させること！
- **(B) サブ情報（属性・累積時間・日数タグ等）の常時表示全カット**:
  - 氏名セルの直下に並んでいた「遅パ」「16日 / 80.0h」などのタグやバッジ表示を、スマホ画面のときには一切常時表示させない（レンダリングおよびCSSからのスキップ）。
- **(C) 氏名列全体の 100px〜110px サイズ制限と省略演出（Ellipsis）**:
  - 従業員氏名セルの幅を **`width: 105px; min-width: 105px; max-width: 105px;`** 程度に厳格に制限。
  - お名前文字（テキスト）部分に以下の CSS スタイルを確実に反映させて1行スマートに折り止める：
    ```css
    font-size: 0.82rem; /* 約13px */
    font-weight: 700;
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
    max-width: 95px;
    ```
  - 表の「従業員」というヘッダー名称も短縮して「氏名」または「スタッフ」とする等、100px内に余裕を持って入れる。

### 2. 詳細情報の補完UI（従業員セル・ワンタップ/クリックポップオーバー＆ドロワー）
サブ情報（勤務時間など）を消したため、従業員セルをスマホ等でタップ（クリック）した際にサッと浮かび上がり、すぐに閉じられる **簡易ポップオーバー（または軽量モーダルカード）** を設計・導通させてください！

#### ◆ インターフェース設計方針
- **起動トリガー**: 氏名セル（または中のテキストバッジ）への `onClick` （タップ / クリック）。
- **表示 UI**:
  - `App.jsx` 内に選択中の従業員情報を一時保存するステート（例: `const [selectedEmployeeForDetail, setSelectedEmployeeForDetail] = useState(null)`）を設定。
  - バッジが選ばれると、画面中央（あるいは画面下方からの軽量ドロワー調）にエレガントな半透明ガラス風モーダル・ポップカードが現れる。
- **表示すべき内容（簡潔で美しいカードデザイン）**:
  - 👤 **フル氏名** & **属性ラベル**（例: 遅バ・正社員など）
  - 🕒 **当月累積実績**: 例 `出勤日数: 16日 / 累積勤務時間: 80.0時間`
  - 📅 **基本ルールや付加事項があれば箇条書き表示**
  - ✖ **閉じるボタン** （背景のオーバーレイ表示部分または閉じるボタンのシングルタップ/クリックで一瞬で消え、シフト編集へ戻れる仕様！）

### 3. シフトセルの表示領域確保（CSSレイアウト強化）
左列の100pxスリム化で 110px 以上広がるメインカレンダー視野を最大限利用します：
- **シフト文字の 2段スマート構成（視認性の確保）**:
  - 狭い幅のセルでも時間が文字崩れしないよう、`17:00` / `~22:00` などの開始時間と終了時間を適切な行間（`line-height: 1.15; font-size: 0.76rem; padding: 2px 3px;` 等）で上下2段のシャープなレイアウトにて折り返す。
- **無駄な外枠の全削減**:
  - メインカード周りの膨らむラベンダー色背景マージンや厚すぎる `glass-card` のパディングをぎゅっと削り、スマホ横幅 100% を余すとこなくカレンダー表示に充てること。

### 4. 【スマホ vs PC】スクロール操作とズームのスマート住み分け（最重要ルール）
- **📱 スマホ表示 (`<= 768px`)**:
  - 左固定が 100px になった広大カレンダーを、**ユーザーの親指（指先）スワイプ・ドラッグだけで快適に滑るように動かす仕様を主役にする**。
  - スワイプの圧倒的な操作性を邪魔し、マスタッチの誤作動の原因になりうる **「左右の半透明フロートスクロールボタン（◀ ▶）」は常時100％完全に非表示 (`display: none` 等)** とする！
- **💻 PC表示 (`> 768px`)**:
  - **デフォルト一画面フィット (100%)**: 初期表示時は30日分＋氏名がオーバーフローなしで美しく100%で画面にすっぽり収まる設計とする。
  - **ズーム機能**: 「➕／➖／100%フィット」のコントロール部から拡大を行った際に、オーバーフロー（見切れたエリア）の発生検知（`scrollWidth > clientWidth`）と連動し、はみ出た瞬間のみ **両端へ「半透明オーバーレイのスクロールボタン」を優雅に浮き上がらせる仕様**とする！
