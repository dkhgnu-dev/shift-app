# P2 指示書: Cycle 7 画面表示面積の最大化と「PC一画面フィット ＆ スマホ快適タッチ横スクロールの極限昇格」

## 背景・目的
Cycle 6 にて実装された半透明フロートスクロールボタンについて、PCとスマートフォン（タッチ環境）では **「求められる操作感と画面の特性が全く異なる」** ことを踏まえた、至高の UI/UX 最適化・面積最大化を行います。

### ◆ 本質的な使い分け（Kazumax・Air 共同設計）
1. **PC（マウス・大画面環境）の理想像**
   - **初期デフォルト**：一ヶ月（30〜31日）分の表が一画面の横幅にピタッと収まって見える状態（横スクロールなし＝矢印ボタンは静かに自動消滅して非表示）。
   - **ズーム時**：拡大ボタンでセルを広げて見切り（オーバーフロー）が発生した**その瞬間だけ**、両際に半透明のフロート矢印（◀ ▶）が浮き上がって発動し、クリックでスイスイ移動可能に！
2. **スマホ（タッチスワイプ・細長スクリーン環境）の理想像**
   - **初期デフォルト**：親指や指先で押しやすい快適な大きめのセルサイズを維持！スマホで無理に30日分を縮小すると字が読めなくなるためです。
   - **フロートボタンの賢いオフ化**：スマホは指（スワイプ）で誰もが自由に横スクロールできるため、表の左右にボタンを浮かせると**誤タッチの元になり、かつ狭い視界エリアを殺してしまいます**。そのため、**スマホ表示（`isMobileView` 等）のときは半透明の矢印ボタンを完全非表示** とし、指滑りで快適なカレンダー横断空間をフルに確保します！

上記に加えて、全体的に無駄な外枠の余白や巨大パディングを取り去り、**PC・スマホともに「画面面積の最大化（広々とした表の描画）」** を実践してください。

## CC（P3 実装担当）への技術・詳細指示

### 1. 画面占有率の最大化（外枠や無駄マージン等の撤収）
- `App.jsx` および `index.css` にて、`activeTab === 'dashboard'`（メインシフト表）が描画される外枠（`glass-card`、マージン、パディング）の空きを大幅にシェイプアップしてください。
- テーブルを内包するエリアが、画面の幅・高さ領域（`height: calc(100vh - 120px)` 等）を最大限フル活用して広く見せる構図へ引き締めること。

### 2. ズーム（拡大縮小）コントロールエリアの創設
- テーブル上部等（月度切り替え付近やアクションエリア）に、ワンタッチで表・セルのスケールや幅を可変できる **ズーム操作部** を配置：

```jsx
// ズームバー構造例
<div className="zoom-controls" style={{display: 'flex', alignItems: 'center', gap: '6px', background: 'var(--glass-bg)', padding: '2px 8px', borderRadius: '8px', border: '1px solid #E5E7EB'}}>
  <button onClick={() => handleZoom(-1)} style={{padding:'4px'}} title="縮小">➖</button>
  <span style={{fontSize: '0.85rem', fontWeight: 'bold', minWidth: '45px', textAlign:'center'}}>{zoomLevel}%</span>
  <button onClick={() => handleZoom(1)} style={{padding:'4px'}} title="拡大">➕</button>
  {!isMobileView && <button onClick={() => setZoomLevel(100)} style={{fontSize: '0.75rem', padding: '2px 6px', background: '#EEF2FF', color: '#4F46E5', borderRadius: '4px'}}>一画面フィット</button>}
</div>
```

### 3. PCにおける「100% 一画面フィット」＆ フロート矢印ボタンの動的連動
- **PC（`!isMobileView`）の場合**:
  - `zoomLevel === 100` 時は、全日付が横スクロールバーなしでちょうど画面幅に入るように調整（フォントや `min-width`、またはスケールを最適に反映）。
  - テーブルの `scrollWidth > clientWidth`（横があふれているか）と連動し：
    - あふれていない時（または限界まで右／左にスクロールし切った側）：半透明フロートスクロールボタン（◀ ▶）を **自動的にフェードアウト（見えなくなるように）させること！**
    - あふれている時のみ：フロートボタンが出現して移動できるようサポート。

### 4. 【最強の例外】スマホ版（モバイル表示）におけるスワイプ至上主義最適化
- **スマホ（`isMobileView === true`）の場合**:
  - 親指での操作性を守るため、セルのサイズは十分に大きくタップしやすいサイズ（例：従来の見えやすい設定、または `min-width: 45px〜50px` 等）をキープすること。
  - スワイプでスムーズに横スクロールできる強みを邪魔させないため、**「左右の半透明フロートボタン（◀ ▶）」は常時完全に非表示（描画・可視化しない）」** とし、指先が自由に動ける領域を 100% 保障してください！

アプリヘッダー及び各種バージョン表記を **`v4.25` から `v4.26`** へと更新してください。
