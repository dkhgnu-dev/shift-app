# Cycle 11 P2 Dex監査済み実装指示書

## 1. 結論

Air Blueprintは採用する。ただし、曖昧だった勤務判定・休息時間の境界・氏名抽出・再計算方法を本書で固定する。

- 作業ブランチ: `cc-cycle11`
- 実装範囲: `frontend/` と本Cycleの文書のみ
- 完成版: `v4.36`
- `backend/`、API、DB、solver、保存形式は変更禁止
- `main` へはmergeしない。P3完了後にDex(P4)レビューへ渡す
- CCクルー補助レビューを必須とする（後述）

## 2. 実装構成

健全性判定と名字抽出は `frontend/src/cycle11Utils.js` の純粋関数に分離する。`App.jsx` 内へ判定ループや名前解析を直書きしない。

推奨公開関数:

- `parseShiftRange(cell, shiftMaster)`
- `isWorkingCell(cell, shiftMaster)`
- `buildHealthAlerts(matrix, shiftMaster, options?)`
- `extractSurname(name)`

戻り値の名称は変更可。ただし、各セルを `[employeeIndex][dayIndex]` で即時参照でき、次の情報を保持すること。

- 連勤警告: 連続勤務日数
- 休息不足警告: 直前勤務からの休息分数
- 同一セルで両方該当できること

計算量は従業員数E、日数Dに対して `O(E * D)` とする。render中に従業員ごとの全期間を何度も走査しない。

## 3. 健全性判定の確定仕様

### 3.1 勤務日・非勤務日の分類

勤務日として数える:

- `shiftMaster` に実在し、`開始～終了` を正しく解析できる通常シフト
- `__custom__` を含む自由時間シフトで、`shiftMaster` の時間帯を正しく解析できるもの
- 特殊シフト `応援`、`店長会`、`研修`、`勉強会`

連勤を切る非勤務日:

- 空セル、未配置、shiftなし
- `休`
- `希望休`
- `公休`
- `有休`
- 削除済み・未知ID、時間形式不正など勤務実態を確定できないセル

`有休` は勤務時間集計上8時間でも、実際に出勤する日ではないため連勤を切る。未知値を推測で勤務扱いしない。

### 3.2 6日連続勤務

- 1行を左から右へ1回走査する
- 連続勤務日数が6になったセルと、それ以降の連続勤務セルだけを警告する
- 5連勤までは警告なし
- 7連勤なら6日目と7日目に警告
- 非勤務日でカウンタを0へ戻す
- 表示期間の先頭より前、末尾より後はデータがないため推測しない。Cycle 11では表示中の16日～翌15日内だけを判定する

表示文言例:

- `6連勤`
- 編集画面: `現在6日以上の連続勤務中です（連続6日目）`

法令違反と断定せず、シフト確認用の健康目安であることが分かる表現にする。

### 3.3 勤務間インターバル

固定のシフト名や「遅番」「早番」という名称ではなく、実時刻で判定する。

- 前日の終了と翌日の開始を両方解析できる場合だけ計算する
- 休息分数 = `(24 * 60 - 前日終了分) + 翌日開始分`
- 休息が `11時間未満（660分未満）` のとき、翌日のセルだけを警告する
- ちょうど11時間は警告しない
- 前日または翌日が非勤務、特殊シフト、未知ID、時刻不正なら判定しない
- `24:00` は1440分として正しく扱う
- 日をまたぐ `終了 < 開始` の勤務パターンは現行仕様外なので推測せず、P3報告へ記載して停止確認する

必須境界例:

- 22:00 → 翌8:15 = 10時間15分: 警告
- 21:00 → 翌8:15 = 11時間15分: 警告なし
- 22:00 → 翌9:00 = 11時間: 警告なし
- 24:00 → 翌9:00 = 9時間: 警告

表示文言例:

- `休息短`
- 編集画面: `前日の勤務終了からの休息が10時間15分です（目安11時間未満）`

### 3.4 リアルタイム再計算と履歴

- `generatedResult.matrix` と `shiftMaster` だけから `useMemo` 等で警告を派生計算する
- 警告を `generatedResult`、localStorage、API payload、Undo/Redoスナップショットへ保存しない
- 直接編集、セル消去、スワップ、ランダム入力、自動生成、Undo、Redoでmatrixが変われば自動的に再計算される構造にする
- 警告計算から `setState` するeffectを作らない。再描画ループを防ぐ
- `isError`、鍵持ち、希望休、固定セル、メモ等の既存表示を上書きしない

## 4. 警告UI

- セル内に小さな非操作要素として表示し、既存の全面 `.cell-hit-target` buttonを維持する
- 警告要素は `pointer-events: none`
- nested buttonや独立したタップ領域を追加しない
- セルの`aria-label`と`title`へ警告内容も含める。色だけで伝えない
- 両警告が同じセルに出る場合も読め、セル高が極端に増えない表示にする
- セル編集モーダルにも、そのセルの警告詳細を表示する
- 警告バッジ追加後も横スワイプ判定、短タップ編集、PC drag/drop、2点スワップを壊さない

## 5. 氏名列の折りたたみ

### 5.1 状態と操作

- `isNameColumnCollapsed` はUI専用state、初期値false
- localStorage、Undo/Redo、generatedResultへ保存しない
- PC・スマホの両方で使用可能
- 氏名ヘッダー内または直近に専用buttonを1個置く
- buttonには `aria-expanded` または `aria-pressed`、状態が分かる`aria-label`と`title`を付ける
- スマホの操作面は最低44px相当を確保する。ただし列幅自体は28pxへ畳めるよう、ボタンを列外へ重ねる等で設計する
- 行の氏名セルは折りたたみ中もタップ・Enter・Spaceで従業員詳細を開ける

### 5.2 幅と表示

- 展開時は現行幅を維持する（スマホ82px、PC140px）。Blueprintの80～85px指定は現行スマホ幅を指すものとする
- 折りたたみ時はPC・スマホとも `28px` に固定する
- `display:none`は禁止
- tableまたはwrapperへ状態classを付け、CSSで `width/min-width/max-width` を一括変更する。各セルへのstyle直書きは避ける
- PCではドラッグ列40pxを残し、氏名列のsticky leftは40px
- スマホではドラッグ列非表示のまま、氏名列のsticky leftは0
- 展開/折りたたみでヘッダーと全行の幅・境界が一致し、日付列へ重ならないこと

### 5.3 名字ヒント

`extractSurname` の契約:

- null等は空文字
- 前後空白を除去
- 半角または全角スペースがあれば最初の語を名字とする
- スペースがない名前は推測で分割せず、元の名前を返す

折りたたみ表示:

- 縦書きまたは省スペース表示を用い、`opacity: 0.6`前後
- `title`とアクセシブル名には必ずフルネームを残す
- 現行の `K.D.`、`T.M.(1)` も識別可能にする
- PCの属性・勤務時間バッジは折りたたみ中だけ非表示にし、展開時に復元する

### 5.4 スクロール・Zoom共存

- 折りたたみ切替で `scrollLeft` を0へ戻さない
- 切替後に既存の`computeFitZoom`と`updateScrollButtons`が新しい幅を再計測する
- 再計測はDOM反映後に1回だけ行う。state更新の無限ループを作らない
- 既存のzoom一時100%測定・`try/finally`復元契約を変更しない
- 必要なら既存の再計測effect依存へ折りたたみstateを追加する
- 幅transitionを使う場合は短時間にし、`prefers-reduced-motion`へ配慮する

## 6. 恒久テスト

### 6.1 純粋関数テスト

`cycle11Utils.test.jsx`等へ小さなfixtureで追加する。

- 5連勤は警告なし
- 6連勤は6日目だけ
- 7連勤は6・7日目
- 休、空、希望休、公休、有休で連勤リセット
- 応援、店長会、研修、勉強会は連勤へ計上
- 削除済み・未知IDは安全側で非勤務
- 22:00→8:15、21:00→8:15、22:00→9:00、24:00→9:00
- 片側が非勤務・特殊・時刻不正なら休息警告なし
- 両警告の同居
- 半角スペース、全角スペース、スペースなし、空値の名字抽出

### 6.2 App結合テスト

巨大fixtureをケースごとに描画しない。2名・必要最小日数を基本とする。

- 初期matrixで警告が表示される
- 直接編集で警告が即時に出る/消える
- スワップ後に対象が移り、Undo/Redoで元の警告へ戻る
- 警告バッジ上の短タップ/横スワイプが既存セル操作契約を壊さない
- 折りたたみbuttonのaria状態、class、28px用DOM、再展開
- 折りたたみ中も氏名セルから詳細を開ける
- 768pxはスマホ、769pxはPCという既存境界を維持
- 折りたたみ切替後に再計測処理が呼ばれ、zoom復元順序契約を壊さない

テスト数を増やすためだけの重複renderは禁止。純粋関数テストを主軸にし、App結合テストは操作連動だけを担保する。

### 6.3 実行条件

現行 `frontend/vitest.config.js` の `pool: 'forks'` と `maxWorkers: 2` を維持する。

1. Cycle 11対象テスト
2. `npm test` を同じ条件で連続2回
3. 既存time utilsテスト
4. `npm run build`

全回タイムアウト0、全件PASSを報告する。失敗時にworker数を増やして押し切らない。

## 7. ブラウザ実機確認

`320 / 375 / 768 / 769 / 1280px` で確認し、スクリーンショットまたは座標実測をP3報告へ残す。

- 展開/折りたたみ時のsticky位置、ヘッダー・行の幅一致
- 名字ヒントとフルネーム詳細導線
- 日付列との重なり、横スクロール、左右フロートボタン
- PC zoomの手動変更、フィット、resize往復
- セル短タップ、横スワイプ、交換、drag/drop
- 6連勤、休息短、両方同居、編集後解除、Undo/Redo復元
- console error / warningなし

実機確認不能の場合は合格扱いにせず、理由を報告してDexへ明示する。

## 8. CCクルー必須監査

本Cycleはロジック・レスポンシブCSS・既存ジェスチャー・テスト性能が交差するためCCクルーを使う。

- クルーA: 勤務分類、6日境界、11時間境界、24:00、未知ID、Undo/Redo再計算を独立監査
- クルーB: 28px sticky列、320～1280px、セルタップ/スワイプ/drag、zoom再計測を独立監査
- クルーCまたはCC本体: unrelated diff、テスト重複render、timeout、バージョン表記を監査

各指摘は採用・不採用と理由をP3報告へ記録する。CCクルーの確認はDex(P4)の代替ではない。

## 9. 禁止事項と停止条件

- solver制約へ6連勤や11時間ルールを追加しない
- 法定違反・残業判定などへ意味を拡張しない
- 既存履歴スナップショットへ派生警告やUI折りたたみstateを追加しない
- 表全体を日ごと・従業員ごとに重複走査する実装を作らない
- Blueprint外のデザイン刷新や依存追加をしない
- Git conflict、保存形式変更、深夜跨ぎ勤務の扱いが必要になった場合は停止してKazumax/Dexへ確認する
