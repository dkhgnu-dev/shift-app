## 3. `targetHours` のデータ契約

### 保存値

- 従業員オブジェクトへ任意項目 `targetHours` を追加する。
- 保存可能値は `null` または有限の正数だけとし、保存形式は `number | null` に統一する。
- UIは `step="0.5"`、入力範囲は `0.5` 以上 `744` 以下とする。
- 空欄だけを「未設定」として `null` に正規化する。
- 新しい入力の `0`、負数、`NaN`、`Infinity`、数値に完全変換できない文字列、上限超過は保存しない。利用者へ入力エラーを示し、モーダルを閉じない。
- `value || null` のような暗黙変換は使わず、有限数判定と範囲判定を明示する。

### UI

- 従業員追加・編集モーダルに「月間目標計上時間」の数値入力を追加する。
- 補足文で「16日から翌月15日までの目安。通常シフトの拘束時間と特殊勤務の計上時間を合計し、休憩時間は控除しません」と明示する。
- 新規追加時は必ず空欄へリセットする。
- 編集時は対象従業員の値を読み込み、項目がない既存従業員は空欄にする。直前に編集した人の値を引き継がない。
- 従業員一覧では、表示が過密になる場合は目標値の追加表示を必須としない。

### 既存データと初期値

- 既存データは読み込み時に各従業員を `{ ...employee, targetHours: normalizedValue }` の形で補完し、他の項目を消さない。
- `targetHours` がない、`null`、空文字、既存保存値の `0` は `null` として読む。既存の数値文字列は、範囲内の有限な正数だけ数値へ変換する。負数、非数、非有限値、744超は `null` とする。
- `INITIAL_DATA` と「デフォルト構成へ戻す」の目標時間は未設定とする。契約日数から値を推測して埋めない。
- このリポジトリには従業員データの独立したエクスポート・インポート機能は存在しないため、今回その機能を新設しない。保存先は既存の `employees` state と `shift_employees` localStorageだけとする。
- `targetHours` は表示用のフロントエンド項目であり、`generateShift` / 再生成のバックエンドpayloadへ追加しない。
- 既存従業員の編集で `targetHours` だけを変更した場合、作成済みの `generatedResult` を破棄しない。氏名、雇用区分、資格、鍵、契約日数、希望休、勤務可能シフト等の生成条件または行構造が変わる場合と、新規追加・削除の場合は従来どおり破棄する。
- 雇用区分を変えても `targetHours` を自動変更しない。編集キャンセル時は元データを変更しない。

## 4. 目標計上時間との差分

- `契約日数 × 8時間` の計算を完全に削除する。
- 名称は「残業」「残業・不足」「配置時間差分」ではなく「目標計上時間との差分」に統一する。
- 実績値は現行どおり、休憩控除前のシフト開始から終了までの経過時間と特殊シフト既定時間の合計を使う。
- 比較対象の `targetHours` も同じ意味の「配置目安時間」であり、法定労働時間・給与計算・残業判定ではない。
- 有効な目標値がある場合だけ `delta = 実績 - targetHours` を計算する。
- `delta > 2` は超過、`delta < -2` は不足、`-2 <= delta <= 2` は標準とする。ちょうど `-2` と `+2` は警告にしない。
- 未設定または不正な保存値は色分けせず「目標未設定」と表示する。
- PCの氏名セル内とスマホの従業員詳細の双方で、同じ判定関数と同じ文言を使う。
- 通常シフトだけでなく、有休・応援・店長会・研修・勉強会の既定計上時間も現行仕様どおり合計へ含める。
- 小数表示は既存UIに合わせつつ、`-0.0h` を出さない。

## 5. 希望休ランダム入力

### 保護と同期

- 実行前の確認ダイアログとキャンセル時無変更を維持する。
- 既存の「希望休」「休」だけをクリアし、通常シフトと特殊シフトを含む確定セルを絶対に変更しない。
- 配置後の各従業員の `requests` は、同じ行のマトリクスに実在する「希望休」セルから再構築する。

### 終了が保証される抽選

- ランダムな日番号をガード回数まで繰り返す方式を廃止する。
- 各従業員について、空きセルの日一覧を先に作り、Fisher-Yates等で一度だけシャッフルして必要数を先頭から選ぶ。
- 日別集中を避ける既存の `maxPerDay` は「優先条件」として扱う。上限未満の空き日を先に選び、それで足りない場合は他の空き日も候補にする。
- 空きセルが必要数以上あれば、乱数運の悪さだけで不足させてはならない。
- 空きセル自体が必要数未満のときだけ、配置可能数まで反映して不足として記録する。

### 不足通知

- 全従業員の更新を一度の整合したstate更新として完了してから、1件の通知に不足者をまとめる。
- 各行に従業員名、目標日数、実際の配置日数を示す。
- 不足理由は「既存確定シフトを保護したため空き日が不足」と明示する。
- 不足がない場合は不足通知を出さない。

## 6. 必須テスト

`frontend/src/App.cycle8.test.jsx` を中心に、少なくとも以下を恒久テスト化してください。

1. 既存localStorageに `targetHours` がない従業員がクラッシュせず「目標未設定」になる。数値文字列は数値へ、0・負数・非数・744超は未設定へ安全に正規化し、他項目を保持する。
2. 新規追加モーダルは目標時間が空で、別の従業員を編集した値を引き継がない。
3. 有効値を保存・再描画するとlocalStorageから復元される。
4. 空欄は未設定となり、新規入力の0・負数・非有限値・上限超過は保存されない。744と小数値は保存・復元できる。
5. `targetHours` がバックエンドpayloadに含まれない。
6. 実績64h・目標64hの短時間勤務者は標準になる。
7. 差分がちょうど `-2h` と `+2h` は標準になり、それより外だけ超過・不足になる。
8. PCとスマホ詳細で「目標未設定」と同じ差分判定を表示する。特殊勤務の既定時間も計上される。
9. ランダム入力をキャンセルすると何も変わらない。
10. 通常シフトと特殊シフトの確定セルを保持する。
11. 十分な空きがある場合、乱数列に依存せず抽選目標数を満たす。
12. マトリクスの希望休と `employees[].requests` が完全一致する。
13. 空き不足時は配置可能分だけ反映し、不足者・目標・実配置数を通知する。
14. 目標時間だけの編集では作成済みシフトを保持し、生成条件の編集では破棄する。
15. 新規追加、編集キャンセル、雇用区分変更、デフォルトリセットで目標値が漏れたり勝手に変わったりしない。
16. 既存の再実行時非累積と日別分散テストを維持する。

重いテスト状態はlocalStorageへ事前投入し、22個のselect操作のような不要な連続再描画を避けてください。タイムアウト値を伸ばすだけの対応は禁止です。

## 8. CCクルー利用判断

**CCクルー利用: 推奨**

理由:

- localStorageの従業員データ構造、追加・編集・リセットの複数経路に触れる。
- ランダム処理と二つのstateの同期を同時に修正する。
- 通常テストだけでは境界値や既存データ互換の見落としが起きやすい。

CCクルーへ確認させる観点:

- `targetHours` の未設定・不正値・既存データ互換と `number | null` の保存型
- 新規・編集・キャンセル・リセット間の値の漏れと、目標だけの編集時のシフト保持
- バックエンドpayloadが無変更であること
- 確定シフト保持と、空きが十分な場合の目標数保証
- `matrix` と `requests` の同期
- ±2h境界とPC/スマホ表示の一致
- テストが実装と同じ誤りをなぞっていないか

CC本体は、使用した場合はP3報告に「CCクルー補助レビュー結果」と採否を要約してください。不使用の場合は理由を書いてください。CCクルーはDex(P4)の代替ではありません。

## 9. デクスクルー監査の統合

サブレビュー利用判断: 使用。

理由: 保存データの任意項目追加、既存データ互換、ランダム処理、表示判定を同時に扱うため、独立視点で境界値と影響範囲を点検する価値がある。

Dex本体はAir草案、実コード、デクスクルー結果を照合し、次を採用しました。

- 既存データへ推測値を補わない。
- `targetHours` をフロントエンドだけの任意項目とする。
- 空き日の列挙と一回のシャッフルで抽選終了を保証する。
- 入力境界、画面間の一致、バックエンドpayload非変更を恒久テストへ追加する。
- 保存形式を `number | null` に統一し、新規入力の0や不正値をエラーにする。
- 特殊勤務も合計される実装に合わせ、名称を「目標計上時間との差分」とする。
- 目標時間だけの編集では作成済みシフトを保持する。

主な指摘の採否:

- 採用: 保存型統一、744時間上限、既存値正規化、編集経路の状態分離、存在しないexport/import要件の除外、名称修正、抽選終了保証、追加テスト。
- 一部調整して採用: 既存保存値の0は互換性のため未設定へ正規化するが、新しい0入力はエラーにする。
- 不採用: なし。
- 保留: なし。
