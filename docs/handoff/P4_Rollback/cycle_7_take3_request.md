# Cycle 7 Take3 修正指示

## 結論

Cycle 7 Take2はP4 NGです。フィット倍率の算出方法と恒久テストを修正し、`cc-cycle7`へpush後、DexへP4再レビューを依頼してください。`main`へはmergeしないでください。

## 修正対象

- `frontend/src/App.jsx`
- `frontend/src/App.cycle7.test.jsx`
- 必要に応じて`frontend/src/index.css`

## 原因

実ブラウザでは`table.scrollWidth`をCSS zoom後の値として扱えません。現在の倍率で除算する処理は、自然幅を過大評価します。また`min-width:100%`の影響で、広いコンテナではテーブルのレイアウト幅自体が拡張されます。

テスト側の`scrollWidth = naturalWidth * zoom`モックも実ブラウザと一致しないため、誤りを検出できません。

## 期待する状態遷移

1. 初期表示:
   - PCでは未縮小時の基準幅を正しく取得・保持する。
   - コンテナに収まる最大倍率を適用する。
2. 「画面にフィット」:
   - 現在倍率に関係なく、同じ画面幅・同じ表なら同じ最大フィット倍率へ戻る。
   - すでにフィット済みなら倍率を変えない。
3. resize:
   - 画面が広がれば、収まる範囲で倍率を上げる。
   - 画面が狭くなれば、必要な範囲で倍率を下げる。
4. タブ復帰・対象期間変更:
   - 基準幅が変わる可能性がある場合は再計測する。
5. 手動拡大縮小:
   - 拡大でオーバーフローしたときだけフロートボタンを表示する。

実装方法はCC判断で構いませんが、現在倍率で`table.scrollWidth`を除算する方式は使用しないでください。初期100%時に測った基準幅をrefへ保持する、またはCSSの`min-width`影響を受けない計測方法を使ってください。

## 受入確認

1. 1280px初期表示:
   - 倍率約55%
   - `container.scrollWidth <= container.clientWidth`
   - 左右フロートボタン無効・非表示
2. 1280pxでフィット済みのまま「画面にフィット」:
   - 55%前後を維持し、50%へ下がらない
3. 1280pxで手動拡大後に「画面にフィット」:
   - 初期と同じフィット倍率へ戻る
4. 1280px -> 1600px resize:
   - 倍率が約55%から約74%へ上がる
   - 全月表示を維持する
5. 1600px -> 1280px resize:
   - 初期と同じ約55%へ戻る

数値はブラウザの端数処理で1%程度ずれても構いませんが、画面拡張時に倍率が下がる動作は禁止です。

## テスト修正

- `scrollWidth = naturalWidth * zoom`というモック前提を削除する。
- 実ブラウザ同様、基準となる自然幅はzoomとは独立した値として扱う。
- フィット済みで再度ボタンを押しても倍率不変のテストを追加する。
- コンテナ幅を800 -> 1000等へ広げてresizeイベントを発火し、倍率が上がるテストを追加する。
- 狭く戻した際に元の倍率へ戻るテストも追加する。
- descriptorは従来どおり`try/finally`で復元する。
