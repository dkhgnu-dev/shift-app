# Cycle 8 Take2前 - Air(P1)仕様再整理依頼

Cycle 8はP4 NG。CCへ直接Take2を依頼する前に、Airが「時間差分」の業務仕様を再整理する。

## 修正対象

- 従業員ごとの月間目標時間の持ち方
- 実績時間が休憩込みか、休憩控除後か
- 目標未設定時の表示
- 希望休ランダム入力で空き日が足りない場合の扱い
- 超過表示テストの安定化と重要経路の恒久テスト

## 期待する状態遷移

- 正しい目標時間がある: 同じ時間単位の実績との差を不足・標準・超過で表示する。
- 目標時間がない: 残業判定を出さず「目標未設定」と表示する。
- 希望休日数を配置できる: 確定シフトを保持して希望休と`requests`を同期する。
- 空きが足りない: 配置可能分だけ反映し、不足した従業員・希望数・配置数を明示する。

## 受入確認

1. 3h・4h・5h・6h・7h・8h系の従業員を契約どおり配置しても、誤った大量不足にならない。
2. 正社員の実績と目標で休憩の扱いが同じ単位になっている。
3. `-2.0h`と`+2.0h`は標準、境界超過だけが青・赤になる。
4. 確定シフトが多く希望休日数を満たせない場合、黙って成功せず不足を通知する。
5. 確定済み通常シフトを希望休ランダム入力後も保持する。
6. `matrix`と`employees[].requests`の希望日が一致する。
7. フロントテストを2周実行し、全件が標準timeout内でPASSする。

## 触らない範囲

- バックエンドのシフト自動生成制約
- API通信方式
- Cycle 7の固定列・ズーム機能
- VersionはTake2実装完了まで`v4.30`から先へ進めない

## Airに決めてほしいこと

1. 月間目標時間を従業員ごとの入力項目として追加するか。
2. 既存ユーザーの初期値・移行値をどうするか。
3. 休憩時間をどのデータから控除するか。現状取得できない場合、表示名を「残業」から「配置時間差分」へ変えるか。
4. 空き不足時の通知UI。
