# Cycle 13 要望: 生成UI整理とスタンプ再タップ消去

## Kazumax確定方針

### 1. 自動生成ボタンの整理

通常利用では「空欄自動作成」を主操作として見せる。
「最適化シフトを生成」は機能を削除せず、詳細操作・その他メニューなどへ移す。

理由:

- 空欄自動作成は、入力済みセルをすべて残して空欄だけを埋めるため、普段の操作に合う。
- 最適化シフト生成は、手動確定セルを残しつつ過去の自動生成セルを並べ直す上級操作である。
- 同じ強さのボタンが二つ並ぶと違いが分かりにくく、誤操作につながる。

必須条件:

- PCとスマホの両方で、通常表示する主ボタンは「空欄自動作成」とする。
- `generateShift()`および再最適化機能自体は削除しない。
- 再最適化は「詳細操作」「その他」などから到達可能にする。
- 再最適化の実行前に「手動入力は残し、自動生成部分を作り直す」ことが分かる確認を出す。
- キーボード操作、スマホメニュー、全画面表示を壊さない。

### 2. 同じスタンプを再度押したときは空欄へ戻す

スタンプモード中、現在セルに入っているシフトと選択中スタンプが同じ場合、そのセルを初期の未記入状態へ戻す。

例:

- 空欄へ`④`をスタンプ -> `④`
- そのセルを`④`スタンプでもう一度選択 -> 空欄
- 空欄へ`希望休`をスタンプ -> `希望休`
- そのセルを`希望休`スタンプでもう一度選択 -> 空欄

必須条件:

- 同一スタンプ判定は、許可シフト検証より先に行う。従業員の許可シフト設定が後から変わっていても、既存セルの消去は妨げない。
- 空欄化では`shift`だけでなく、`hours`、`note`、`isFixed`、`isError`などセル固有情報を残さない。
- 希望休を空欄へ戻した場合、`employees[].requests`も`buildRequestsFromMatrix()`経由で即時同期する。
- 1回の空欄化をUndo/Redo履歴の1操作として記録する。
- Undoで元セル全体を復元し、Redoで再び空欄になる。
- 空欄化後もスタンプモードと選択中の筆は維持し、連続操作できる。
- タップ、クリック、キーボードEnter/Spaceで同じ結果になる。
- スワイプ、セル交換、通常セル編集との干渉防止を維持する。
- 異なるスタンプを押した場合は、従来どおり上書きする。

## Air設計時の確認事項

- 「詳細操作」のPC/スマホ共通UIを、既存デザインに沿って最小変更で決める。
- 現在の`isStampNoOp()`を削除・改名・toggle関数化する場合のテスト更新範囲を示す。
- `App.cycle12.test.jsx`と`cycle12Utils.test.jsx`へ恒久回帰テストを追加する。
- 実装時の正しいversionは、作業開始時の最新mainから採番する。未実装のversionを先に固定しない。

## 役割と進行

Air(P1)がBlueprintを作成する。スタンプ履歴・希望休同期・既存生成導線にまたがるため、Blueprint完成後はDex(P2)事前監査を通し、CC(P3)が実装する。
